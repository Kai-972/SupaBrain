## Per-stage log
- S0 (Lane A): Claude Code drafted the monorepo scaffold, zod config loader, shared types/interfaces (copied from the human-written brief), test fakes and guard scripts. Kai set the plan and decisions. Verified by `pnpm build`, `pnpm test`, `pnpm lint:hardcode`, `pnpm check:secrets` and a live Rabdi `eth_chainId` check in `pnpm run doctor`.
- S1 ENS (Lane A): Claude Code read the ENSv2 docs, wrote the registration/registry/agent/proof/kill scripts, the tx runner and the `EnsAuthority` (14 tests written before the implementation). Kai decided the design and approved funding. Verified on chain: every step was dry-run with `eth_call` simulation first, post-checked from chain state, and the agent boundary and kill switch were proven with the agent's own key and mined reverts.
- S1 Arkiv (Lane A): Claude Code read the Arkiv MCP guides and the installed SDK 1.0.1 source (the docs lag the package), wrote `packages/arkiv` with 34 tests before the implementation (gas rule, per-signer queue, guarded send, schemas, body codec), then ran the spike on Rabdi in dry-run-then-broadcast steps. Kai set the plan and funded the wallets. Verified: every write was simulated first, results were read back through SDK queries and cross-checked with the Arkiv MCP `verify_tx`/`verify_entity` tools; refusals (`NotOwner`, `ReadOnlyEntity`, `ExpiryNotExtended`) were produced by the live chain; an AI error caught along the way (assuming the node hid revert data when it was our own wrapper) is logged in `arkiv/friction.md`.
- S2 memory core (Lane A): Claude Code designed and wrote the engine, memory service, Arkiv store, sync, dashboard API and MCP tools, tests first for every authority rule (the UI fixture's revoke invariant is a test). Kai set the scope (core first, no deploy yet) and the domain. Verified live: real MCP calls as three agents (`pnpm e2e:memory`, 11/11), a real Claude Code session, a restart that rebuilt the graph from Arkiv alone, and a second server instance proving the watcher. Lane B's independent review found three real bugs in the MCP layer (path-token log leak, stack-trace leak, log forging); fixed with their tests.
- S3 undo (Lane A): Claude Code wrote dry run, revoke, Keep, Correct this and Add context with the C-UI fixture story as the test (written through the real service), then proved it live with `pnpm e2e:undo` (14/14) and a restart that restored revocations, corrections, Keep and notices from Arkiv. Kai set the order (core first).
- S4/S5 (Lane A): Claude Code mounted Lane B's payments (adapters, MCP tools, approvals privacy, payment memories), wrote pairing and the demo seed, and ran Lane B's `ens:add-vendor` for acme after a dry run. Tests first for the mount and pairing; verified live (acme resolves via the Universal Resolver, pairing → connected on SSE, seed → Arkiv). The live P1/P3 run waits for Lane B's keys.
